# TapGlyph — анимация Glyph после уведомления об оплате

Небольшое Android-приложение для Nothing Phone (2). Оно управляет световыми зонами Glyph через официальный Nothing Glyph Developer Kit и может реагировать на платёжные уведомления выбранных приложений.

## Что умеет

- Кнопка **«ТЕСТ АНИМАЦИИ»** запускает световой sweep по зонам Glyph Phone (2).
- `NotificationListenerService` проверяет уведомления только от пакетов, указанных в настройках TapGlyph.
- Если TapGlyph открыт на экране, подходящее уведомление запускает анимацию.
- Если TapGlyph в фоне, приложение публикует нейтральное уведомление. Нажатие на него открывает TapGlyph и запускает анимацию.
- Текст уведомления, сумма и данные покупки не сохраняются и не выводятся в собственное уведомление.

## Важное техническое ограничение

Android не предоставляет стороннему приложению универсальное событие «другая платёжная программа только что завершила NFC-операцию». TapGlyph поэтому не перехватывает NFC и не узнаёт результат банковской транзакции напрямую: он реагирует на уведомление банка/кошелька, похожее на подтверждение покупки.

Кроме того, официальный Glyph Developer Kit разрешает управление Glyph только пока приложение находится на переднем плане. Поэтому без взаимодействия пользователя анимация не может гарантированно запускаться, когда TapGlyph свёрнут. В этом случае используется уведомление TapGlyph с действием «нажать, чтобы запустить».

Фактическая работа зависит от того, отправляет ли конкретная версия СберБанк Онлайн, Mir Pay или другого кошелька уведомление о покупке и совпадает ли пакет приложения с фильтром. Уведомления, отключённые в настройках банковского приложения или системы, отследить нельзя.

## Требования

- Nothing Phone (2), Nothing OS и Android 14 или новее.
- Разрешение на доступ к уведомлениям для TapGlyph.
- Разрешение Android на публикацию уведомлений TapGlyph.
- Для тестового Glyph SDK: включённый режим отладки Glyph.

## Сборка APK через GitHub Actions

В workflow используется `android-actions/setup-android@v4` с явным `packages: platform-tools`. Не добавляй пакет SDK с именем `tools`: Google удалил старый пакет, а `sdkmanager` завершает работу с ошибкой `Failed to find package 'tools'`. Современные command-line tools устанавливаются самим action; Android Platform 35 и Build Tools 35.0.0 устанавливаются следующим шагом workflow.

1. Создай пустой репозиторий на GitHub.
2. Загрузи в него все файлы этой папки (содержимое проекта, а не ZIP-файл).
3. Открой вкладку **Actions**. Если GitHub попросит включить Actions, разреши запуск workflow.
4. Выбери **Build TapGlyph APK** → **Run workflow** → **Run workflow**.
5. Дождись зелёного статуса сборки и открой завершённый запуск workflow.
6. Внизу страницы найди **Artifacts** и скачай **TapGlyph-debug-apk**.
7. Распакуй скачанный архив — внутри будет `TapGlyph-debug.apk`.

Workflow сам получает официальный `KetchumSDK_Community_*.jar` из репозитория Nothing, кладёт его в `app/libs` только на время CI-сборки и собирает APK. SDK JAR не хранится в этом проекте.

Сборка запускается также при push в `main`/`master` и для pull request.

## Установка и настройка на телефоне

1. Установи `TapGlyph-debug.apk`. При необходимости разреши установку APK из используемого файлового менеджера.
2. Включи параметры разработчика и USB-отладку, подключи телефон к компьютеру с Android Platform Tools и выполни:

   ```bash
   adb shell settings put global nt_glyph_interface_debug_enable 1
   ```

   Nothing указывает, что debug-режим автоматически отключается примерно через 48 часов. При необходимости команду можно повторить.
3. Открой TapGlyph и нажми **«ОТКРЫТЬ ДОСТУП К УВЕДОМЛЕНИЯМ»**. В системных настройках разреши TapGlyph доступ к уведомлениям.
4. Разреши TapGlyph отправлять уведомления Android, когда система спросит.
5. Оставь включённым переключатель **«Отслеживать уведомления об оплате»**.
6. Проверь поле **«Приложения-источники»**. По умолчанию там `ru.sberbankmobile,ru.nspk.mirpay`. Сохрани список. Если приложение использует другой package name, замени его здесь.
7. Нажми **«ТЕСТ АНИМАЦИИ»**. Приложение должно быть на экране, чтобы официальный Glyph SDK мог управлять подсветкой.

### Как узнать package name приложения

Подключи телефон с включённой USB-отладкой и выполни, например:

```bash
adb shell pm list packages | grep -Ei 'sber|mirpay|wallet'
```

Скопируй нужное значение после `package:` в поле приложений-источников TapGlyph. На Windows вместо `grep` можно использовать `findstr`.

## Как работает реакция на оплату

- **TapGlyph открыт:** подходящее уведомление от выбранного приложения вызывает анимацию сразу.
- **TapGlyph свёрнут:** появляется собственное уведомление TapGlyph. Нажми его — приложение откроется и включит анимацию.
- **TapGlyph закрыт/выгружен системой:** Android может задержать доставку уведомления Notification Listener до запуска процесса. Это зависит от версии Nothing OS и фоновых ограничений.

Фильтр проверяет только текстовые маркеры покупки/оплаты и отбрасывает сообщения с явными признаками ошибки или отмены. Это эвристика, а не подтверждение банковской транзакции; возможны пропуски и ложные срабатывания.

## Локальная сборка

Требуются JDK 17, Android SDK Platform 35 и Android Build Tools 35.0.0.

```bash
./gradlew :app:assembleDebug
```

При локальной сборке положи официальный `KetchumSDK_Community_*.jar` в `app/libs/`, иначе код соберётся, но управление Glyph на устройстве не заработает (приложение покажет статус об отсутствующем SDK).

## Примечания

- В манифесте оставлен `NothingKey=test` для разработки. Это тестовый APK, не production-релиз.
- Для публикации/production-сборки следуй актуальным условиям API key из официальной документации Nothing.
- Проект не запрашивает NFC-доступ, не эмулирует карту, не подключается к банковским API и не хранит платёжные данные.
